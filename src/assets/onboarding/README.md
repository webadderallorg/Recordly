# Onboarding

`RecordlyDemoVideo` loops a 2.5-second theme-matched still (`public/auth/recordly-banner-light.png` or `recordly-banner-dark.png`) with a restrained screen filter and slow 1 → 1.045 zoom, followed by the complete silent demo video. Each video ending returns to the still and restarts the sequence. Theme changes immediately select the matching PNG. Reduced motion keeps the matching still without zoom or video playback. Hidden documents pause playback and resume from the still. Failed video playback retains the still. This shared sequence is used by onboarding, sign-in and Cloud; the Cloud side panel frames the image/video directly without mockup chrome.

Onboarding has two carousel pages: Account and Permissions, selected with the bottom pagination buttons. The Recordly logo sits inline with the brand name in the welcome and permissions headings. Account requires a non-anonymous Supabase session; there is no skip action. The shared banner uses
`public/auth/recordly-demo.mp4` through `RecordlyDemoVideo` in `src/components/auth/OnboardingLayout.tsx`. Sign-in and Cloud use the same full-bleed demo: four clips showing recording, a notes demo, publishing, and shared-video feedback, in that order (Projects 46, 51, 43, 50), with hard cuts. Each clip has its own light screen-filter pass (pixel texture, scanlines, colour fringe, and vignette). The publishing clip (Project 43, third in the sequence) stays flat, with no added orbit, rotation, tilt, or perspective. The shared-video feedback clip (Project 50, last) keeps its stronger one-way perspective motion. Recording, notes, and shared-video feedback use stronger, unique one-way orbit/perspective sweeps, restarting at each cut. The first clip sweeps anticlockwise. Motion must never rock or tilt back toward its starting pose within a shot: interpolate monotonically between distinct projected screen poses, with no oscillating motion clock. Keep the screen filter restrained so the footage stays clear. Future additions follow these same independent-motion rules. The silent video plays once per still/video cycle; the old `public/auth/recordly-demo.jpg` poster is retained as an asset. The banner expands to fill spare height, while both pages share heading typography, logo size, and spacing. Page content scrolls in compact windows while the footer actions and bottom navigation remain visible.
Permission controls and the final Start recording action live in
`src/components/auth/OnboardingPermissions.tsx`.

The dedicated onboarding window is frameless on every platform, with a drag strip and an in-app close button. It opens as a centered square whose side is 85% of the usable display height (clamped to the usable width). Opening it brings it to the front and focuses it once. On macOS and Windows, the Dev settings "Show onboarding" preview reveals the Recordly mark over a fullscreen backdrop, fades in the popup, and then fades out the backdrop. Reduce Motion opens the popup immediately.

Signed-in users open directly into Permissions. Returning signed-out users use the compact sign-in popup. The onboarding window paints a branded loading shell while renderer modules or the session load; opening onboarding does not wait for editor project hydration. First onboarding plays `public/audio/first-boot.m4a` once, with a mute/unmute control. Only successful playback is remembered; blocked autoplay retries on the next interaction. Reopening onboarding does not replay completed music or show an inactive sound control. There is no fullscreen startup animation.
